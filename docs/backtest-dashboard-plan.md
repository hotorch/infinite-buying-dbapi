# 초보자용 경량 백테스트 대시보드 계획

## 목표

수강생이 로컬에서 날짜와 조건을 고르고 `백테스트 실행`을 누르면, 순수 무한매수 V4의 결과를 숫자와 차트로 쉽게 이해할 수 있게 한다.

첫 버전은 여러 실행을 비교하는 분석 도구가 아니라 **현재 실행 한 건을 정확히 설명하는 한 화면**에 집중한다. 차트의 모든 선과 마커는 범례와 쉬운 한국어 설명을 제공하며, 같은 용어를 툴팁과 체결 내역에서도 반복해서 사용한다.

## MVP 원칙

- 화면은 한 페이지, 전략은 순수 무한매수 V4 하나만 제공한다.
- 입력은 확정 기본값을 먼저 채우고, 사용자는 필요한 값만 바꾼다.
- 결과는 핵심 요약 → 차트 읽는 법 → 차트 → 체결 내역 순서로 보여준다.
- 가격, 자산, 낙폭은 하나의 시간축과 크로스헤어를 공유한다.
- 색상만으로 의미를 전달하지 않고 `기호 + 쉬운 이름 + 색상`을 함께 쓴다.
- 초보자용 이름을 먼저 표시하고 기술 용어는 괄호 안에 보조로 적는다.
- 로그인, 다크모드, 결과 공유, 자동 최적화, 종목 확장은 첫 버전에서 제외한다.
- 프런트엔드 상태 관리 라이브러리는 추가하지 않고 React 기본 상태만 사용한다.

## 확정 기본값

| 항목 | 값 |
|---|---|
| 종목 | TQQQ |
| 분할 수 | 40 |
| 초기 자본 | $10,000 |
| 입력 자본 범위 | $1 ~ $3,000 |
| 기간 | 최근 완료된 미국 거래일 기준 최근 5년 |
| 가격 | 액면분할과 배당을 반영한 수정 OHLC |
| 수수료 | 매수와 매도 각 체결금액의 0.04% |
| 슬리피지 | 미반영 |
| 세금 | 미반영 |
| 주식 수량 | 정수 주식만 허용 |
| 비교 기준 | TQQQ는 TQQQ·QQQ·SPY, SOXL은 SOXL·SMH·SPY의 같은 기간 매수 후 보유 |

시작일이 휴장일이면 다음 미국 거래일을 사용하고, 시작일 이전 5거래일은 워밍업에만 사용한다. 첫 주문에 필요한 금액이 입력 자본보다 크면 실행하지 않고 필요한 최소금액을 안내한다.

## 한 화면 구성과 동작

1. 상단 입력 패널에서 종목, 분할 수, 초기 자본, 시작일, 종료일을 선택한다.
2. `백테스트 실행`을 누르면 진행 상태를 `데이터 확인 → 전략 계산 → 결과 준비`의 세 단계로 보여준다.
3. 결과 위에는 실제 적용된 종목, 기간, 분할, 자본, 수수료, 가격 기준을 한 줄로 다시 표시한다.
4. 핵심 요약에는 총수익률, CAGR, MDD, 최종자산, 동일 ETF·기초 ETF·시장 대비 성과, 완료 사이클 수를 표시한다.
5. 요약 아래에 `차트 읽는 법` 안내 상자를 두고 다음 세 문장을 기본으로 노출한다.
   - 초록·빨강 막대는 그날의 가격 움직임입니다.
   - 파란 선은 내가 산 평균가격, 별표는 별지점 주문이 발생한 날입니다.
   - 아래쪽 자산과 낙폭 차트도 같은 날짜를 함께 가리킵니다.
6. 차트는 가격·체결, 전략 자산·세 벤치마크, 낙폭의 세 패널을 하나의 시간축으로 보여준다.
7. 차트에 마우스를 올리거나 키보드로 날짜를 이동하면 세 패널이 같은 날짜를 가리키고, 상세 툴팁을 표시한다.
8. 체결 내역은 기본적으로 접어 두고, 펼치면 사이클 경계와 쉬운 체결 종류를 포함한 표를 보여준다.
9. 전체 결과 JSON과 체결 내역 CSV를 내려받을 수 있게 한다.

화면에는 다음 경고를 항상 표시한다.

> 과거의 백테스트 결과는 미래의 수익이나 성과를 보장하지 않습니다. 수수료 0.04%를 제외한 슬리피지와 세금은 반영되지 않았습니다.

## 초보자용 범례

범례는 차트 캔버스 안에 작게 넣지 않고 차트 바로 위의 HTML 영역에 둔다. 기본 범례는 자주 보는 항목만 보여주고, `전체 범례 보기`를 누르면 상세 항목을 펼친다.

### 기본 범례

| 표시 | 쉬운 이름 | 의미 |
|---|---|---|
| 캔들 | 하루 가격 | 초록은 상승일, 빨강은 하락일 |
| 파란 실선 | 내 평균가격 | 현재 보유 주식의 평균 매수가 |
| 주황 점선 + `★` | 별가격 | 별지점 주문을 계산하는 기준 가격 |
| 파란 원 + `B` | 매수 | 주식을 산 날 |
| 빨간 네모 + `S` | 매도 | 주식을 판 날 |
| 회색 세로 점선 + 숫자 | 사이클 완료 | 한 사이클이 끝난 날짜와 순번 |

### 전체 범례의 체결 셀

| 엔진 역할 | 화면 표시 | 설명 |
|---|---|---|
| `initial_buy` | `B 첫 매수` | 사이클을 시작한 매수 |
| `avg_half_buy` | `½ 평균가 매수` | 절반 금액을 평균가격 기준으로 매수 |
| `star_half_buy` | `★½ 별지점 반 매수` | 절반 금액을 별가격 기준으로 매수 |
| `star_full_buy` | `★ 별지점 전액 매수` | 한 회분 전체를 별가격 기준으로 매수 |
| `star_quarter_sell` | `★¼ 별지점 일부 매도` | 보유 수량 일부를 별가격 기준으로 매도 |
| `target_sell` | `T 목표가 매도` | 목표 수익 가격에서 나머지를 매도 |
| `reverse_first_sell` | `R 역방향 첫 매도` | 역방향 모드의 첫 매도 |
| `reverse_sell` | `R 역방향 매도` | 역방향 모드의 추가 매도 |
| `reverse_buy` | `R 역방향 매수` | 역방향 모드의 재매수 |

범례 항목에 마우스를 올리거나 초점을 두면 한 줄 설명을 다시 보여준다. 범례 기호, 차트 마커, 툴팁 체결 셀, 체결 표 배지는 모두 같은 표시와 문구를 사용한다.

## 차트 툴팁

툴팁은 날짜와 수치만 나열하지 않고 `가격`, `내 상태`, `오늘의 체결` 세 묶음으로 구분한다.

- 가격: 시가, 고가, 저가, 종가
- 내 상태: 평균가격, 별가격, 목표가격, T, 보유수량, 현금, 총자산
- 비교: 전략 수익률, 동일 ETF·기초 ETF·시장 수익률, 현재 낙폭
- 오늘의 체결: 해당 날짜의 체결 셀을 시간순으로 표시

마우스를 사용하지 못하는 경우를 위해 차트 아래에 `선택한 날짜 상세` HTML 영역을 두고 같은 내용을 텍스트로 제공한다.

## 백테스트 결과 계약

Python 엔진은 UI가 다시 계산하지 않아도 되도록 다음 값을 완성된 JSON으로 반환한다.

```text
request
  symbol, division_count, capital, start_date, end_date

summary
  total_return, cagr, mdd, final_equity, benchmarks[],
  cycle_count, trading_days, buy_count, sell_count

assumptions
  ruleset_version, price_basis, fee_rate, slippage, tax,
  warmup_sessions, benchmarks[], requested_dates, effective_dates, digest

daily[]
  date, open, high, low, close, avg_cost, star_price, target_price,
  t, quantity, cash, invested, equity, benchmark_equities, drawdown, cycle_id

events[]
  date, side, role, quantity, price, fee, reason_code, cycle_id

weather_research[]
  symbol, weather_state, horizon_sessions, sample_count,
  average_return, win_rate, worst_return, through_date
```

숫자 계산과 역할 판정은 Python에서만 수행한다. TypeScript는 표시 형식과 상호작용만 담당한다.

날씨의 과거 표본은 선택한 ETF가 해당 `weather_state`로 전환된 세션의 종가부터 60거래일 뒤 종가까지 계산한다. 종료일 뒤 가격은 사용하지 않으며, TQQQ 통계를 SOXL 표본으로 대체하거나 그 반대도 하지 않는다. 날씨 분류 자체는 TQQQ에 QQQ, SOXL에 SMH를 신호로 쓰고 공통으로 SPY 상대강도를 사용한다.

## 구현 구조

- `dashboard/`: Next.js 16, React 19, TypeScript 한 페이지 화면
- 차트: `lightweight-charts` 5.2 단일 의존성
  - 캔들, 선, 이벤트 마커, 다중 패널, 공유 크로스헤어를 한 차트 인스턴스에서 처리한다.
  - 필수 TradingView 저작자 표시와 링크를 화면 하단에 포함한다.
- Python: 기존 `strategy.py`를 그대로 사용하는 일봉 백테스트와 성과 계산
- Next.js 서버 경로: 검증된 JSON을 Windows에서 셸 없이 Python 프로세스의 표준입력으로 전달하고 결과 JSON을 받는다.
- 로컬 전용: 기본 바인딩은 `localhost`이며 DB증권 인증정보와 실주문 기능을 사용하지 않는다.
- 전략 규칙을 TypeScript로 중복 구현하지 않는다.

프런트엔드 컴포넌트는 역할이 분명한 수준으로만 나눈다.

```text
BacktestForm
ResultSummary
ChartLegend
BacktestChart
SelectedDateDetails
TradeHistory
```

## 가벼운 구현 순서와 검증 지점

### 1. Python 백테스트 엔진

- CSV 전처리와 거래일 범위를 먼저 검증한다.
- LOC, LIMIT, MOC 체결을 보수적으로 판정한다.
- 수수료, 일별 평가금, 종목별 세 벤치마크 비교, 총수익률, CAGR, MDD를 계산한다.
- 기본값 한 건을 JSON fixture로 저장해 사람이 체결과 최종 결과를 확인한다.

검증: 같은 입력의 결과와 digest가 항상 같고, 기존 전략 테스트가 모두 통과해야 한다.

### 2. JSON 계약과 로컬 API

- 입력 검증과 오류 메시지를 추가한다.
- `$1` 미만 또는 `$3,000` 초과, 날짜 역전, 지원하지 않는 종목과 분할 수를 명확히 거부한다.
- Python 오류를 초보자가 이해할 수 있는 한국어 메시지로 변환한다.

검증: 정상 fixture와 주요 오류 케이스의 계약 테스트가 통과해야 한다.

### 3. 한 페이지 대시보드 골격

- 입력 패널, 진행 상태, 가정 요약, KPI 6개를 연결한다.
- 기본값 실행 한 건만 먼저 지원한다.
- 새 실행을 하면 현재 결과를 교체한다.

검증: 인터넷과 DB증권 키 없이 기본 실행이 완료되어야 한다.

### 4. 차트와 범례

- 가격, 전략 자산·세 벤치마크, 낙폭 패널을 만든다.
- 기본 범례와 전체 범례를 연결한다.
- 별지점 마커, 매수·매도 마커, 사이클 경계를 표시한다.
- 공유 크로스헤어, 툴팁, 선택한 날짜 상세를 연결한다.

검증: 화면에 나타나는 모든 선과 마커에 대응하는 범례가 있고, 색상을 보지 않아도 기호와 문구로 구분할 수 있어야 한다.

### 5. 체결 내역과 다운로드

- 접이식 체결 표와 사이클 구분선을 추가한다.
- 차트 체결 셀을 선택하면 해당 표 행을 강조한다.
- JSON과 CSV 다운로드를 연결한다.

검증: 차트, 툴팁, 범례, 표에서 같은 역할이 같은 이름과 기호를 사용해야 한다.

### 6. 최종 확인

- Python 전체 테스트를 실행한다.
- 대시보드 lint, typecheck, production build를 실행한다.
- 기본값 실행, 오류 입력, 차트 툴팁, 범례 확장, 체결 행 이동을 브라우저에서 확인한다.
- 1280px 데스크톱과 768px 태블릿 폭에서 내용이 잘리지 않는지 확인한다.

## MVP 완료 기준

- 인터넷과 DB증권 키 없이 기본 데이터로 실행된다.
- 같은 입력은 항상 같은 결과와 digest를 만든다.
- 초보자가 입력을 바꾸지 않아도 기본값으로 바로 실행할 수 있다.
- 모든 차트 선과 마커는 `기호 + 쉬운 이름 + 색상` 범례를 가진다.
- 날짜를 선택하면 가격, 내 상태, 비교 결과, 당일 체결을 한곳에서 볼 수 있다.
- `$1` 미만, `$3,000` 초과 또는 첫 주문이 불가능한 자본은 필요한 최소금액과 함께 거부된다.
- 요청 기간과 실제 거래 기간, 수정주가, 수수료 가정이 결과에 기록된다.
- JSON과 CSV 다운로드가 동작한다.
- 기존 전략 및 전체 테스트가 통과하고 대시보드 production build가 성공한다.
